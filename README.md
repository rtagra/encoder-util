# encoder-util

Browser-only utilities. No server, no build step — everything runs in your browser. Page views are counted with Google Tag Manager (GTM-NWTM4N47); no input, secret or token is sent.

## Google Tag Manager — do not alter the tag

The GTM snippet in the `<head>` of every HTML page was generated by Google and must NOT be altered, reformatted, moved, or replaced by any agent or developer updating this code. Change analytics in Google Tag Manager, not in these files.

### Adding a new page — always add the Google Tag

Exception: `json-api.html` has NO Google Tag, by design — it contains the OpenAPI tab, and bank OpenAPI specs are confidential, so no page view is sent while working there. Do not add the tag to that page. (The old standalone `openapi.html` is now a redirect to `json-api.html#openapi`; see "Tabs & redirects" below.)

### Adding a new page — always add the Google Tag (continued)

Every new HTML page MUST include the exact GTM snippet in its `<head>`, verbatim, with the DO NOT ALTER comment above it. Copy it from `new-page-template.html` — do not retype it, do not use a different tag, do not load it from a JS file. Then add the page to the menu (`<nav>`) in every HTML file, with `class="active"` on its own page, and add it to the home-page grid and the table below.

Live (GitHub Pages): https://rtagra.github.io/encoder-util/

## SEO — submitting to Google

Every tool page has a unique `<title>`, `<meta name="description">`, canonical URL, Open Graph / Twitter tags, and JSON-LD structured data. `robots.txt` and `sitemap.xml` are in the repo root.

To submit to Google:
1. Go to [Google Search Console](https://search.google.com/search-console) and add the property `https://rtagra.github.io/encoder-util/` (URL-prefix property).
2. Verify ownership — use the HTML-tag method and paste the verification `<meta>` into `index.html` (ask Bossing to add it), or the HTML-file method.
3. In Search Console: Sitemaps → add `https://rtagra.github.io/encoder-util/sitemap.xml` → Submit.
4. Request indexing for the home page, then wait — Google usually indexes a small new site in days to a few weeks. Check coverage in Search Console, not by searching immediately.

## Tools — 5 combined pages, 12 tools as tabs

The top menu has 6 items: Home + 5 category pages. Each category page has a tab bar (`js/tabs.js`); clicking a tab shows that tool and updates the URL hash, so every tool is still directly linkable, e.g. `encoders.html#base64`. The home page is organised into the same 5 category sections, linking straight to each tool's `#tab`.

| Page | Tab (`#hash`) | Tool JS | What it does |
|---|---|---|---|
| Home | — | — | `index.html` — links to all tools, grouped by category |
| Encoders | `#url` | `js/url.js` | URL Encoder / Decoder — `encodeURIComponent` / `encodeURI`, decode with error handling |
| Encoders | `#base64` | `js/base64.js` | Base64 Encoder / Decoder — Unicode-safe, standard + URL-safe |

### Tabs & redirects

- Tab switching is in `js/tabs.js` (shared, no dependencies). It reads the hash on load, updates it on click (`history.replaceState`, so back/forward still works via `hashchange`), and fires a `encoderutil:tab` window event on activation.
- The OpenAPI tab is lazily initialised: `json-api.html` only calls `openApiInit()` the first time the `#openapi` tab is shown, because Swagger UI renders badly while its panel is hidden. The other tabs' tools run their normal init on page load (`jwtInit()` / `computeHash()` on `crypto.html`).
- The 12 old single-tool filenames (`url-encoder.html`, `base64-encoder.html`, `hex-base64.html`, `jwt.html`, `hash.html`, `cert-formatter.html`, `json-formatter.html`, `openapi.html`, `regex-tester.html`, `date-formatter.html`, `uuid-generator.html`, `cidr-calculator.html`) are kept as lightweight redirects — `meta refresh` + `location.replace()` + canonical link to the new `#tab` URL, `noindex, nofollow`, no GTM — so existing bookmarks don't break. Do not delete them without updating the links above.
- `sitemap.xml` lists only `index.html` and the 5 combined pages.

Shared code: `js/common.js` (Base64 / Base64URL, HMAC via Web Crypto, timestamp hover formatting), `css/style.css`.

## JWT notes

- **Secret is a parameter:** type it in the Secret field on the encode / decode pages. It is masked by default (Show / hide button), never stored, never sent anywhere.
- **Hover timestamps:** mouse over `exp`, `iat` or `nbf` in the decoded JWT — the tooltip shows the human-readable local time, e.g. `8 Nov 2026, 14:30:00 WIB (in 2h)`, plus relative time.
- **Demo only for signing:** don't paste a production secret into any web page. Real JWT signing belongs on a server. Decoding is safe — it only reads the token.

## Host on GitHub Pages

```bash
git init
git add .
git commit -m "encoder-util: browser-only URL, Base64 and JWT tools"
git branch -M main
git remote add origin https://github.com/rtagra/encoder-util.git
git push -u origin main
```

Then in GitHub: Settings → Pages → Deploy from a branch → `main` / `/ (root)` → Save.
Visit https://rtagra.github.io/encoder-util/

## Test locally

```bash
python3 -m http.server 8000
# open http://localhost:8000/
```

Or just open `index.html` — note: Web Crypto (`crypto.subtle`, used for JWT signing) requires a secure context, so JWT encode/verify needs `http://localhost` or `https://`, not a plain `file://` open.
